# 🌐 WebOrder Telegram Bot — Production-Ready Engine

Профессиональный модульный Telegram-бот на **pyTelegramBotAPI (`telebot`)** для приёма заказов, интерактивного сбора ТЗ (инженерного квиза), онлайн-оплаты через Telegram Payments (Invoices) и полноценного управления заказами через панель администратора.

---

## 🚀 Архитектура и структура проекта

Монолитный скрипт полностью разделён на чистую, легко масштабируемую модульную структуру:

```
Python-bot/
├── config.py             # Конфигурация, валидация .env, каталоги услуг, опций, кейсов портфолио
├── database.py           # SQLite3 менеджер (CRUD пользователей, заказов, оплат, индексы)
├── texts.py              # Мультиязычная локализация (RU / EN / UZ) и функция t()
├── states.py             # Состояния конечного автомата (FSM OrderQuiz и AdminState)
├── keyboards.py          # Генераторы Inline/Reply клавиатур с мультиязычностью
├── utils.py              # Защитные обёртки API, html.escape, парсер callback_data, калькулятор сметы
├── handlers/
│   ├── __init__.py
│   ├── user.py           # /start, /help, /lang, меню, прайс-лист, FAQ, интерактивное портфолио
│   ├── quiz.py           # 5-шаговый интерактивный квиз сбора ТЗ (мультикнопки ✅/⬜, back/cancel)
│   ├── payment.py        # Telegram Invoices, выбор депозита (30%/50%/100%), pre-checkout, чеки
│   └── admin.py          # Админ-панель: фильтры, пагинация, смена статусов, ответ клиенту через бота
├── main.py               # Главная точка входа: инициализация FSM, фильтров, надёжный polling
├── bot.py                # Обратная совместимость для запуска через `python bot.py`
├── requirements.txt      # Зависимости проекта
├── .env.example          # Шаблон переменных окружения
├── Dockerfile            # Докеризация приложения
├── docker-compose.yml    # Запуск бота в контейнере
├── weborder-bot.service  # Юнит-файл для systemd на Linux-сервере
└── .gitignore            # Защита от утечки секретов, БД и логов
```

## 🛠 Ключевые возможности и исправления

### 1. Исправление багов и безопасность
- **Приведение `ADMIN_ID`**: безопасный парсинг в `config.py` с проверкой на `int` и предупреждением в лог, если переменная пустая или некорректная.
- **Безопасная работа с `call.data`**: переход на структурированный разделитель `:` (`action:category:id`) с помощью функции `parse_callback()`. Символ `_` в названиях услуг больше не ломает парсинг.
- **Защита от ошибки Telegram API `message is not modified`**: обёртки `safe_edit_message_text()` и `safe_edit_message_reply_markup()` в `utils.py` перехватывают 400 Bad Request и не спамят в лог.
- **Защита от инъекций и битых HTML-сущностей**: все пользовательские строки (ТЗ, контакты, комментарии) экранируются через `safe_html()` (`html.escape`), что исключает сбои парсера `HTML`.
- **Защита от блокировки бота**: метод `safe_send_message()` перехватывает ошибку `bot was blocked by the user` при отправке уведомлений и сообщает об этом администратору.
- **Надёжный polling**: цикл `infinity_polling` в `main.py` защищён экспоненциальной задержкой (от 3 до 60 сек) при сетевых сбоях и мгновенно завершается при фатальных кодах (401 Unauthorized / 404 Not Found), исключая бесконечный спам.

### 2. Мультиязычность (RU / EN / UZ)
- Полная поддержка трёх языков: **Русский (RU)**, **English (EN)**, **O'zbekcha (UZ)**.
- Предпочтительный язык пользователя сохраняется в SQLite БД (`users.language`) и восстанавливается при перезапуске.
- Быстрое переключение по команде `/lang` или кнопке в главном меню.

### 3. Интерактивный квиз сбора ТЗ (FSM OrderQuiz)
1. **Шаг 1: Выбор типа сайта** — Landing Page, Корпоративный, E-commerce, Portfolio, Blog, Frontend, Custom + отправка текста/референса (или кнопка «⏩ Пропустить»).
2. **Шаг 2: Дополнительные опции** — интерактивные кнопки с переключением `✅` / `⬜` в реальном времени без мерцания (Адаптив, SEO, CRM/Telegram, Копирайтинг, Логотип, Срочность).
3. **Шаг 3: Автоматический расчёт сметы и сроков** — прозрачная калькуляция с возможностью выбрать расчётный тариф, диапазон или ввести свой бюджет текстом.
4. **Шаг 4: Контакты** — кнопка «👤 Использовать мой Telegram» или ручной ввод номера и имени.
5. **Шаг 5: Экран подтверждения** — детальная карточка заявки, выбор депозита (30%, 50%, 100%) и кнопка отправки. Возможность вернуться на любой шаг назад (`◀️ Назад`) или отменить (`❌ Отмена`).

### 4. Панель администратора (`ADMIN_ID`)
- Доступ строго по `ADMIN_ID` (защита от несанкционированного доступа).
- Команда `/admin` или специальная кнопка в главном меню.
- **Фильтрация и пагинация заявок**: вкладки «Все», «Новые», «В работе», «На согласовании», «Завершенные».
- **Смена статуса заявки**: Новая, На оценке, В работе, На согласовании, Завершена, Отменена с **автоматическим уведомлением клиента в боте**.
- **Быстрый ответ клиенту через бота**: админ нажимает «✍️ Ответить через бота», вводит текст, и бот пересылает его клиенту с указанием номера заявки.
- **Базовая статистика**: общее число пользователей, количество заявок по статусам, сумма оплат.

### 5. Живое портфолио и витрина
- Категории: Лендинги, Интернет-магазины, Корпоративные сайты, UI/Вёрстка.
- Карточки кейсов с описанием задачи, используемым стеком (Next.js, FastAPI, Tailwind и др.), конверсионными метриками и кнопкой **«🔥 Хочу похожий сайт»** (с автоподстановкой услуги в форму заказа).
- Раздел **«❓ FAQ / Как мы работаем»**: описание 4 этапов, условия предоплаты, бесплатные правки и 30-дневная гарантия.

## 💻 Установка и локальный запуск

### 1. Клонирование и виртуальное окружение
```bash
git clone https://github.com/Farrux-Developer/Python-bot.git
cd Python-bot

# Создание и активация venv (Linux/macOS)
python3 -m venv venv
source venv/bin/activate

# В Windows PowerShell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 2. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 3. Настройка конфигурации
Скопируйте шаблон `.env.example` в `.env`:
```bash
cp .env.example .env
```
Заполните параметры в `.env`:
```env
BOT_TOKEN=1234567890:ABCdefGhIJKlmNoPQRsTUVwxyZ
PROVIDER_TOKEN=284685063:TEST:NzA3_...
ADMIN_ID=123456789
```

### 4. Запуск бота
```bash
python main.py
```

## 🐧 Развертывание на Linux-сервере (systemd)

1. Склонируйте проект в `/opt/Python-bot`.
2. Создайте виртуальное окружение и установите зависимости.
3. Скопируйте файл сервиса:
   ```bash
   sudo cp weborder-bot.service /etc/systemd/system/
   ```
4. Активируйте и запустите службу:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable weborder-bot
   sudo systemctl start weborder-bot
   ```
5. Проверка статуса и логов:
   ```bash
   sudo systemctl status weborder-bot
   journalctl -u weborder-bot -f
   ```

## 🗄 Структура базы данных (SQLite)

### Таблица `users`
| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | Telegram User ID |
| `username` | TEXT | Никнейм (@username) |
| `full_name` | TEXT | Имя и фамилия |
| `first_seen` | TEXT | Дата первого входа (ISO) |
| `last_seen` | TEXT | Дата последней активности |
| `language` | TEXT | Язык интерфейса ('ru', 'en', 'uz') |

### Таблица `orders`
| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | Уникальный ID заказа |
| `user_id` | INTEGER | Внешний ключ на users(id) |
| `service_type` | TEXT | Тип услуги ('landing', 'corp', 'ecom' и т.д.) |
| `details` | TEXT | Описание задачи / ссылка на референс |
| `options` | TEXT | JSON-список выбранных опций |
| `budget` | TEXT | Выбранный бюджет |
| `estimated_price` | REAL | Расчётная стоимость (USD) |
| `estimated_days` | TEXT | Примерные сроки реализации |
| `contact_info` | TEXT | Контактные данные клиента |
| `status` | TEXT | Статус: new, evaluating, in_progress, review, completed, cancelled |
| `payment_status` | TEXT | Статус оплаты: unpaid, deposit_paid, fully_paid |
| `created_at` | TEXT | Дата создания (ISO) |
| `updated_at` | TEXT | Дата последнего изменения |
